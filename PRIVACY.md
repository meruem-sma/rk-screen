# Privacy

RK Screen is a Windows remote support beta. A person sharing their screen must approve each incoming session and choose a monitor. Mouse/keyboard control, clipboard and system audio require separate permissions. Either participant can end a session. Device names are self-reported and are not verified identities.

Opening the application registers a device identifier with PeerJS Cloud so that another device can request a session. PeerJS Cloud signaling and Google/Cloudflare STUN are used for connection establishment. Those services process network addresses and connection metadata. The current Beta 1 build removes the retired default OpenRelay credentials. A user can explicitly configure a TURN relay in Settings; its password is protected locally with Windows-backed Electron safeStorage and is supplied to that relay during authentication. If direct communication is unavailable and a working relay is configured, encrypted WebRTC traffic may pass through that relay. The optional network check gathers connection candidates without capturing the screen. A short session verification code is derived locally from the connection's certificate fingerprints for manual comparison; it is not a persistent or independently verified device identity.

Screen contents, optional system audio, chat, accepted files and explicitly shared clipboard text are transmitted to the connected participant. There is no application screen recording or cloud chat archive. Chat keeps up to 200 messages in memory; a user can explicitly copy a message or export the current session to a chosen local text file. Received files are stored in the recipient's Downloads folder after acceptance. Up to 20 selected files can wait in the local sending queue; each needs receiver approval. Disconnecting cancels the queue and removes incomplete receiving files. Device settings, recent connections, favorites/local aliases and limited startup/error logs are stored locally. Screen, chat, clipboard and keystroke contents are not intentionally written to those logs.

The optional update check contacts a fixed public GitHub release feed when the user clicks Check for updates. No device/session identifiers are sent by the application in that request. GitHub can process the network address. A newer setup is opened only at the user's request; it is not installed or run automatically. An unsigned release remains unsigned after this check.

Connection reports are saved only when the user selects Save report and chooses a file. They include up to 120 connection/video performance samples. IP addresses, device IDs/names, screen/chat/file contents and relay credentials are excluded. Reports are not sent automatically.

Website/download provider infrastructure is separate from the application. See the [website privacy page](https://rkscreen.com.tr/gizlilik/) and provider policies: [PeerJS Cloud](https://peerjs.com/), [Google](https://policies.google.com/privacy), [Cloudflare](https://www.cloudflare.com/privacypolicy/). For an explicitly configured relay, consult that provider's policy.

Do not disclose passwords, session contents or personal data in public GitHub issues. For security reports see [SECURITY.md](SECURITY.md). The beta has not completed independent security auditing or multi-PC testing across all network environments.
